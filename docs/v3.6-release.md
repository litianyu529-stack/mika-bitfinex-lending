# V3.6：行情窗口、事件回测和快速层起价

初始应用版本为 `0.3.6.0`，保留 `/api/v3`。`0.3.6.1-rc.1` 预览版新增[手动订单两小时保护](manual-order-protection.md)，状态库升级至 Schema 19。本次不改变期限池比例、成交层比例、净年化底线、资金上限、拆单或降价时间表。旧配置的 `quick_pricing_mode` 默认为 `EXPLORATION_V4`，升级代码本身不授予候选实盘资格。

预览版默认使用 V3.5 报价机制。切换到新快速层需要通过真实 90 天、十二情景的策略评估。

## 行情输入

WS 与 REST 成交由统一队列按 ID 去重、批量落库，保存成交原始有符号金额；旧记录方向未知。后台从 SQLite 流式恢复七天，按精确期限维护增量统计和小型不可变快照。LIVE 不逐分钟重新读取或排序七天成交。

统计截尾需要同期限至少 30 笔合法成交、有效样本量至少 10；保留原分位数、支撑量和大额成交例外。稀疏期限保留合法原值并标注。需求使用真实成交笔数和金额。

REST 以内部半开区间分页核验，短页可证明包含空区间的完整覆盖。满页递归细分；单毫秒仍满页时留下不可证明的缺口。不得从最早、最晚成交推断完整性。规则依据 [Bitfinex 历史成交接口](https://docs.bitfinex.com/reference/rest-public-trades)，最高 10,000 笔并遵守该端点限速。资金盘口方向依据 [官方盘口接口](https://docs.bitfinex.com/reference/rest-public-book)。

只有完整七天已核验、统计落后不超过 60 秒且策略指纹一致，才可使用新输入。缺口、错误或过期自动回原输入和报价，Dashboard 显示原因。原始行情保留 90 天，派生分钟统计和增量标记保留 8 天。

研究信号缓存使用私有临时目录。程序在正常返回、Python 异常或 Ctrl+C 时关闭并清理自建缓存。强制终止或掉电时可能留下缓存文件。

## 快速层

新模式 `EXECUTABLE_PREMIUM_V1` 的 `quick_start_premium_apr_points=0.10` 指净年化百分点，例如 6.00% 变为 6.10%。不是相对增加 10%，也不是日利率增加 0.10%。

参考价优先取同期限借款盘口从高到低累计覆盖订单的边际利率；不足整单但至少 150 USD 的深度可用，并标注不足。否则依次取同期限一小时、二十四小时有足够样本的成交量加权中位数；都不足时回旧快速层，不借用其他期限。

目标为参考价换算净年化后加 0.10 个百分点、与该池底线取较高，再按实际费用换算毛日利率并向上取整。新快速层不加旧 5%／Q75 保护或切片微梯。平衡层、高收益层公式保留。

新链使用 `QUICK_EXECUTION_PREMIUM_V1`，固定落点为不加溢价的参考价，继续原快速层十阶段，只能持平或下降。旧链保留原起点、落点、阶段及时间，不批量撤挂。

## 验收与启用

离线引擎按真实时间处理行情、提交确认、部分成交、撤单确认、回款及日结利息，每分钟决策；挂单、占款和贷款持续跨日、跨训练／验证／测试分界。市场成交量只消费一次，触发决策的成交不能填入新单，撤单确认前旧单仍可成交。

历史盘口使用当时可见的采样时间；旧分钟桶到桶结束才可见。缺少新鲜盘口时暂停新增和改价。盘口供给队列、执行延迟、提前回款及日结时点均为明确披露的模型假设，不能当作实际账户成交或收益。实际收益账本另行核算。

固定 A/B/C 对照和完整十二情景、连续 60/15/15 切分、三天移动块 Bootstrap（2,000 次、种子 307）及证书门槛详见 [验证规范](strategy-validation.md)。未通过或不可判定时继续原机制。通过后只对新单整体启用，不设小额试用阶段；原账户、归属与未知写入保护继续有效。

```powershell
python lendingbot.py --config <隔离配置> --evaluate-strategy
# 仅对完整通过 V3.6 验收的新报告执行；实际 Worker 须已停止，之后仍需正常 LIVE 预检与启动。
python lendingbot.py --config <配置> --apply-validated-v36 <已通过完整验收的新报告.json>
```

启用命令重新检查全部证据，将证书绑定完整策略指纹；任何影响策略的参数变更都会使原证书失效。证书不以单个布尔字段作为授权。失败不会改变 ACTIVE 或记录 V3.6 启用事件。

## 数据库与证据

Schema 16 和 18 在在线备份后迁移为 Schema 19，并保留 V3 家族标记。旧 V4 Schema 17 须先走隔离迁移。迁移保留归属、恢复状态、V3.5 历史分界和调价链。V3.6 启用事件单独记录。

策略评估生成的报告默认位于 `.state/research/strategy-validation-report.json`。启用需要包含 `engineVersion=event-v36-v1` 的完整证据。
